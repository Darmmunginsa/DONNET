# ปรับเครื่องมือและเอกสารตามระบบเดิม — 27 กันยายน 2026

สถานะ: เผยแพร่บน Apps Script production แล้ว — Version 2 วันที่ 28 กันยายน 2026 จาก source commit `4e2d471` โดยอัปเดต deployment เดิมและคงสิทธิ์เดิม สำรองฐานข้อมูลก่อนอัปเกรดเรียบร้อย

## รูปแบบอ้างอิง

- ใบเสนอราคา: SalePro `js/pages/pdf.js` และเครื่องมือ `js/pages/quotes.js`
- เอกสารลูกค้า: SalePro `js/pages/saletracker.js`
- PO: PurchasePro `js/app.js`
- ใบส่งของชั่วคราว: Tech `index.html` โทนสีส้ม และไม่แสดงราคา

นำโครงใบเสนอราคาเดิมมาใช้ ส่วนเอกสารอื่นปรับตามรูปแบบเดิมให้เข้ากับ snapshot ของระบบใหม่ ไม่คัดลอกชื่อผู้ลงนามหรือข้อมูลบริษัทที่ hardcode ในระบบเก่า ใช้ข้อมูลบริษัท/ภาพที่ตั้งค่าใหม่

## เครื่องมือ

รายละเอียดหลายบรรทัด, Part No., ราคา Included, ส่วนลดเปอร์เซ็นต์/จำนวนเงิน, หัวข้อ/หมายเหตุ/แถวว่าง/แบ่งหน้า, ลากหรือกดขึ้นลง, ทำซ้ำแถว, เลขลำดับเอง, ความสูงแถว, ฟอนต์สี่ส่วน, ซ่อนคอลัมน์, เส้นแนวตั้ง, ระยะห่าง, สีหลัก, ราคาต่อเดือน/ปี, ผู้เสนอราคา, วันหมดอายุ, Tag/แหล่งที่มา และดูตัวอย่างก่อนบันทึก

รูปแบบบันทึกกับใบเสนอราคา และถูกเก็บใน snapshot เมื่อออกเอกสาร ยอดเงินจริงคำนวณบนเซิร์ฟเวอร์เสมอ ใบเสร็จแสดงยอดงวดที่รับจริง ใบส่งของชั่วคราวจากงานช่างเก็บเฉพาะข้อมูลสินค้าและจำนวน ไม่มีราคา/ต้นทุน

## อัปเดต Apps Script เมื่อจะนำขึ้นใช้งาน

1. สำรองฐานข้อมูลปัจจุบันก่อนอัปเดต นัดช่วงหยุดบันทึกสั้น ๆ เพราะรุ่นเก่าอ่าน schema แบบตรงตัว
2. `npm run check` แล้วแทน Domain.gs, Server.gs, Client.html, Styles.html ด้วย dist รุ่นนี้ (Index/manifest ไม่ได้เปลี่ยน)
3. ใช้ wrapper ชั่วคราว `function upgradeDONNET(){ upgrade_(); }` เพื่อเพิ่ม `Quotations.presentation` และ `QuoteItems.priceText,rowHeight,displayNo` ท้ายตารางเดิม รวมถึงสร้างตาราง CompanyFiles สำหรับคลังบริษัท ห้ามรัน setup_ ทับฐานเดิม
4. นำ wrapper ออกก่อนสร้าง deployment version ใหม่ แล้วอัปเดต deployment เดิมเพื่อคง URL
5. ทดสอบเปิดใบเก่า สร้างร่างใหม่ บันทึก เปิดใหม่ และเอกสารพิมพ์พร้อมบทบาทช่าง

การ rollback ต้องคืนทั้ง source version และสำเนาฐานก่อนเพิ่มคอลัมน์ เนื่องจากรุ่นเก่าตรวจ schema แบบตรงตัว อย่าลบคอลัมน์ที่มีข้อมูลใหม่เพื่อ rollback
